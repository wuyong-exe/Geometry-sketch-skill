> 1. 先读 SKILL.md（骨架 + 硬规则速查 + references 导航）
> 2. 按阶段执行时，逐段 Read 本文件对应章节（阶段 0 → §阶段 0，依此类推）
> 3. 写脚本前 Read references/algorithms.py + template_static.py（或 template_motion.py）照抄

## 阶段 0：意图识别与模式选择

> **核心认知**：初中几何题中，学生需要的数据（1-2 个数字）只是用来计算的，图形的**形状由几何关系唯一确定**。因此绝大多数题目都该走精确模式，示意模式仅在约束严重不足时使用。

### 0.1 判别规则（精确是默认，示意是例外）

**一句话规则**：只要能用尺规唯一画出（差个缩放），就是精确模式。

判别流程：

1. **默认精确模式** — 绝大多数题目的归宿。
2. **仅以下情况降级为示意**：
   - 题目只描述了图形类型但几乎没有几何约束（如"四边形 ABCD 中，E 在 AD 上"）
   - 约束太少以至于图形形状完全不定（如"AB=AC"就没了——顶角可以是任意值）
   - 题目明确说"画一个示意图"或"草图"
3. **坐标系检测**：题目含"一次函数""反比例函数""抛物线""坐标系""x轴""y轴""象限""坐标"等关键词 → 触发 4.2「坐标系规则」：不标任何数字，轴只画箭头+O。
4. **动点模式检测**：题目含"动点""一动点""在…上运动""滑动""移动""绕…旋转""旋转一周""扫过""抛物线上""函数图像上""二次函数图像上"等关键词，且图形随该点变化 → 触发动点模式（`dynamics` 非空）：
   - 输出 PNG 画**默认位置**静态图；HTML 提供**可拖拽动点**交互（拖动时其他图形实时联动）
   - **多动点**：题目含多个"一动点/在…上运动"（如"点 D 是线段 AB 上一动点，点 H 是直线 … 上的一动点"）→ 每个都是独立一级动点（active 数组），逐个参数化（圆上 θ / 线段 t / 直线 t / 曲线 x，见 4.1b params）
   - **关联点**：位置不由自身参数决定、由一级动点派生（如"动点坐标为 (m,0)、其关联点坐标为 (m+3,0)"，或对称/中点/正方形顶点）→ 按题面关系推导进 deps（op 见 3.4；op 表没有的关系用 Python 推导坐标公式，JS 端无感知）
   - **⚠ 动点交互对象 = 题面指定运动对象（硬约束）**：动点必须在题面指定的几何对象上直接拖动——抛物线/函数图像上的动点用 **curve 类型**（在曲线上拖，LUT 最近邻吸附）；**禁止**把曲线动点"映射"成坐标轴/辅助参数点让用户拖动（如把抛物线上的动点偷换成 x 轴上可拖的辅助参数点，用户拖动的是参数而不是题面对象）。例外：题面本身就定义坐标轴参数动点（如"动点 E(m,0)"）→ line 类型，那是题面给定的，不算捷径
   - **动点范围层级（硬约束）**：① 一级动点范围 = 题面计算结果（见阶段 1 动点边界）；② **二级及以上动点（关联点/链式）范围由一级动点沿依赖链推导继承**——关联点无独立滑块/独立范围，其可达位置 = 一级动点范围沿 deps 链逐级 op 映射的结果（三级 = 二级的映射，依此类推；luts/轨迹自动覆盖），**不另行设范围**、不与一级冲突
5. **⚠ 动点语义扩展（2026-08）**：**几何对象上"一点"**（"点 E 为 x 轴上一点""P 为抛物线上一点""Q 在线段 AB 上"等，用"一点"而非"动点"）且**后续含条件锁定/最值/长度表达式**（"当…时""GF=√5·OF""…的最小值/最大值"；**孤立"求…的位置/坐标"不单独触发**，需伴随上述条件/最值/长度之一）→ **判动点模式**（该点可拖、关联点联动、观察条件成立位置）——即使最终求的是**唯一解**（条件等式锁定位置），动点交互仍有教学价值（拖 E 观察 GF/OF 何时到 √5）。PNG 画题面条件解出的默认位置、HTML 提供拖拽探索。典型：坐标系综合题"点 E 为 x 轴上一点，过 E 作 y 轴平行线交…于 F、交抛物线于 G，当 GF=…时求 G 坐标"
6. **结论标记识别（2026-08）**：题目含"下列结论""正确的是""求证""证明""判断""可能为""始终在""最小值为"等结论标记时，解析必须**拆分题设与结论**——**只按题设绘图**（基础题干 + 扩展题干），**结论中的几何对象不画**（射线/延长/特殊位置/最值辅助等图形本体，防泄露答案；**求证基本元素该画**——被证明对象点/线段/三角形/四边形，见 §1.6；**隐藏轨迹照常显示**，见 trajectory 规则；详见阶段 1 §1.6）
- 动点模式下跳过预处理区旋转/翻转兜底（同 axes 豁免），模型构造时自行摆水平
   - **显式圆 vs 隐式轨迹（三类判定）**：
     - ① 题面明说"在…圆上/以…为直径/以…为半径的圆"→ **画可见圆**（circles 定义）
     - ② 仅"旋转一周/绕点转动"→ 轨迹圆**隐式**（不画可见圆，走 luts）
     - ③ **距离约束**（"EF=2""AP=3"，动点绕某点保持定距）→ 轨迹圆同样**隐式**（不画可见圆，走 luts），但题面给出的约束线段（如 EF）**必须画进 segments**——画圆等于泄露轨迹/答案，不画线段等于丢条件
   - 若题目同时含坐标系与动点（如"在 x 轴正半轴上运动"），axes 与 dynamics 同时启用
   - **模板选择**：动点模式 → 使用 4.1b 动点模板；其他模式（精确/示意/坐标系）→ 使用 4.1 静态模板（已验证冻结版，勿改）。注：4.1b 是 4.1 的**动点变体**，编号 `b` 为历史沿用（动点支持后加的），**不是模式名称**——"精确模式"指模式判定默认项，与 4.1/4.1b 模板编号无一一对应关系

**关于数值的角色**：
- 题目给了具体数值（AB=5, ∠A=30°）→ 直接代入，计算更方便
- 题目没给数值 → 自己设一个方便的值（如取圆的半径 r=5，取最长边=6），形状比例由几何约束算出

### 0.2 仅在这些情况下询问用户

以下情况才需要向用户确认，**不要每道题都问**：

- 图形存在多种合理画法且差别很大（如"点 P 在直线 l 上"——可能在 A 的左侧或右侧，距离也不确定）
- 题目描述了多个图形但未说明是画在一起还是分开
- 题目描述自相矛盾（如"AB=5, BC=6, AC=12"——违反了三角形不等式）

询问方式要简洁，给出 2-3 个选项让用户选，不要开放式提问。

### 0.3 示意模式的默认值

示意模式（或精确模式下自选数值）时，无数值约束的距离和角度用**合理默认值**：
- 一般三角形的角：60° / 50° / 70°（和为 180°）
- 等腰三角形顶角：40°，腰长为底边的 1.2 倍
- 直角三角形直角边：3 和 4
- 平行四边形锐角：60°
- 梯形的上下底比：3:2
- 线段上取点：取中点（比例 0.5）

输出后告知用户"此为示意图/默认参数，如需精确尺寸请补充具体数值"。

## 阶段 1：解析几何元素

从题目文字中提取以下结构化信息，以文字列表形式列出：

### 1.1 点 (Points)
列出所有出现的点，标注已知坐标的点（如有坐标系）和待求点。

### 1.2 基本图形 (Shapes)
- 三角形：顶点列表、类型（等腰/等边/直角/一般）
- 四边形：顶点列表、类型（平行四边形/矩形/菱形/正方形/梯形/一般）
- 圆：圆心、半径（或半径约束）

### 1.3 约束关系 (Constraints)
逐条列出题目给出的约束，分类为：
- **长度约束**：AB = 5, AB = AC, AB : BC = 2 : 3 等（约束线段加入 required_segments）
- **角度约束**：∠A = 90°, ∠ABC = 60°, ∠A = ∠B 等——**角的两边必画**（∠ABC → 边 BA、BC 加入 required_segments；角度弧线不画）
- **位置约束**：D 在 AB 上, D 是 BC 中点, AD 平分∠BAC 等（AD 平分线等要素线段必画，见 1.4）
- **关系约束**：AB ∥ CD, AD ⊥ BC, A,B,C,D 四点共圆 等——**关系载体线段必画**（∥/⊥/共线/相等关系中的线段 AB、CD、AD、BC 加入 required_segments）

### 1.4 辅助元素
- **几何要素线段（必画）**：题目明确提到的高线、中线、角平分线、垂直平分线、对称轴、翻折折痕、中位线、直径、半径、弦、切线等——**必须加入 segments（及 required_segments）**，与图形边、连接线同等对待（2026-08：原列为可选辅助元素，漏画不检测；现纳入完整性检测）
- 延长线、截取线段
- **连接线（必画）**：题目说"连接 AD"等连接线**必须加入 segments（及 required_segments）**——与图形边、目标线段同等对待，漏画触发完整性检测 [FAIL]（2026-08）

### 1.5 动点模式解析（阶段 0 触发动点模式时）
- **动点识别（逐个）**：找出**全部**动点及各自运动方式——圆上动（圆心、半径或直径） / 线段上动（所在线段） / 直线上动（所在直线） / 坐标轴上动（哪个轴、从哪截取） / **曲线上动（所在函数曲线 + 题面区间，如"位于线段 BC 上方的抛物线段"）**；未明确时按最典型方式默认（如"以某线段为直径的圆上"→ 圆心 = 该线段中点，半径 = 半长）；每个动点 = 一个一级动点，各自参数化（圆上 θ / 线段 t / 直线 t / 曲线 x）；**曲线动点必须用 curve 类型直接落在曲线上**（禁止映射成坐标轴辅助参数点，见阶段 0 硬约束）；**⚠ 动点边界（一级动点范围必须严格=题面计算结果，硬约束）**：参数化时**能算必算**可动范围写入 param——题面给区间/劣弧/限定段/坐标范围时 → 精确 `t_min/t_max`（直线限定段如"BC 上方"）、`theta_min/theta_max`（弧度，圆上劣弧/上半圆）、`x_min/x_max`（曲线区间）；**仅在题面完全未限定运动方向与区间时**才允许兜底默认（直线 ±3、圆 0~2π）——**禁止拿默认值当题面范围**（如题面说"P 在 x 轴上，1≤x≤3" 必须 t∈[1,3]，不得用 ±3）。**实际可动范围（拖拽 clamp）与滑块两端都以 param 的该字段为准**（严格一致，滑块-300~300 仅对应未限定的默认 ±3）
- **非独立点识别（关联点）**：扫题面找位置不由自身参数决定、由其他点派生的点——"动点坐标为 (m,0)、另一关联点坐标为 (m+3,0)（随前点平移）"、"关于某点对称"、"中点"、"定比分点"、"正方形顶点"、"圆/线段上的从属点"等 → 按题面关系推导进 deps（op 见 3.4；op 表没有的关系用 Python 推导坐标公式，JS 端无感知）
- **显式圆上 vs 隐式轨迹**：题面出现"在…圆上/以…为直径/…为半径的圆"→ 显式画圆（circles 定义该圆）；仅"旋转一周/绕点转动/扫过"**或距离约束**（如"EF=2"，动点绕定点保持定距）→ 圆是隐含轨迹，不画可见圆（circles 留空，轨迹走 luts），但距离约束的线段（EF）必须画进 segments
- **导出依赖识别**：关联点与一级动点的关系——关于点对称、关于线对称、中点、定比分点、平移、正方形顶点等（op 见 3.4）；逐条列出依赖链（允许多级，禁环）
- **trajectory（显示轨迹名单）**：列出**全部一级动点 + 涉及题目所求值的关联点**（所求值对象）；**不含中间构造点**（仅用于推导所求值点的过渡点）；纯图形题（无所求值）→ 只列一级动点。此名单控制 HTML 呈现的轨迹线（2026-08 起**默认呈现**："显示轨迹"勾选框默认勾选，HTML 打开即显示，可取消）——名单为空/缺失时自动回退到全部一级动点。**⚠ 轨迹不受"不画结论"影响（2026-08）**：隐藏轨迹是动点运动路径的自然呈现（虚线、可交互），**区别于可见实线**——结论中描述的轨迹对象（如"F 始终在射线 BC 上"的 F 轨迹）**照常加入 trajectory 显示**；学生拖 P 观察 F 随动运动、自行发现位置关系，正是题目考察的能力（"不画结论"只约束可见实线，如射线 BC 作为图形本体）
- **目标线段识别**：从所求值表达式解析"两点距离"（如"求某点甲到某点乙距离的最小值"）→ 该两点连线 = 目标线段，加入 segments（即使题干没说"连接"；见 4.2 目标线段）
- **一致性**：points 默认位置、dynamics 参数、segments 三者必须一致；关联点若只连一条线需加入 isolated_exempt（不补连，标签保留）
- **方向处理（惯例默认 + 镜像兜底，无需询问）**：当构造存在**多解**（侧向构造未定方向、双侧解、题面方位词 + 无图无法唯一确定）时，**按惯例默认**构造一侧（四边形 ABCD 逆时针环绕；"右侧作正方形" = 沿 a→b 顺时针 = dir−1、"左侧" = dir+1，见 3.4），**不需要询问用户**——用户可在 HTML 用**水平/垂直镜像或旋转**自行调整方向后保存 PNG（镜像即纠错手段）。仅当题面连惯例默认都无法确定（完全无方向信息且无图）时才考虑询问用户

### 1.6 题设 vs 结论区分（解析第 0 步，2026-08）

**核心原则：只按题设绘图，结论中的"关系/结果"不画**（关系结论是学生需自己分辨/求证的内容，画了会泄露答案）；**求证/结论中的基本几何元素该画**（被证明对象：点/线段/三角形/四边形——证明载体，画出不泄露结果、方便学生辨认）。

**解析第 0 步先拆分**：
1. **基础题干**（必画）："如图…"后的图形描述——出现的全部几何对象（点/线/形/动点/连接）都画
2. **扩展题干**（必画）："若…""设…"条件式引入的新点/连接/中点（题目的分析对象，帮助学生理解）——如"若 E 是 DC 的中点，连接 EG"→ 画 E、连 EG
3. **结论拆分为两类**（"下列结论""求证""证明""判断"之后的内容）：
   - **① 基本几何元素（该画）**：被证明对象——点/线段/三角形/四边形等（如"求证 △ABM≌△CDN"→ 画 △ABM、△CDN 的各边 AB/BM/AM、CD/DN/CN；"求证 AM∥CN"→ 画 AM、CN 线段）。**画出不泄露证明结果，学生需辨认基本元素才能证明**；基础题干已含的边（AB/CD/BM/DN）照画，新增的连线（AM/CN）**补画并加入 required_segments**（与 segments 同粒度，防漏画不被完整性检测捕获）
   - **② 关系/结果（不画）**：≌（全等）、∥（平行）、⊥（垂直）、相似、最值、等腰/特殊位置等关系结论——不画标记/特殊构型；其中描述的**射线/延长/特殊位置/最值辅助**作为图形本体不画
   - **隐藏轨迹不受影响**（动点运动路径照常显示，见 trajectory 规则——学生拖 P 观察是解题过程）；结论涉及的连接/中点若属扩展题干则照画（画连接 EG 不画"EG 最小值"的辅助构造）

**精简判别示例**（正方形动点题）：
- 基础题干「正方形 ABCD、AB=4、动点 P 在 AC、以 DP 为边作正方形 DPFG」→ **画**（全部）
- 扩展题干「若 E 是 DC 中点，连接 EG」→ **画**（E 点 + EG 连线）
- 结论①「F 始终在射线 BC 上」→ **射线 BC 不画**——只画正方形本体边 BC 线段（射线是待证明结论）
- 结论②④「∠CPD 可能为 135° / △CDP 等腰时 AP 的值」→ **特殊角度/位置不画**
- 结论③「EG 的最小值为 √2」→ EG 已由扩展题干画；最值相关辅助构造不画

**精简判别示例**（平行四边形全等/平行题）：
- 基础题干「四边形 ABCD 为平行四边形、M、N 在对角线 BD 上、BM=DN」→ **画**（ABCD + 对角线 BD + M/N 在 BD 上）
- 求证(1)「△ABM≌△CDN」→ **基本元素画**（△ABM、△CDN 各边——AB/CD/BM/DN 已在题干，补画 AM、CN）；**≌ 关系不画**（全等标记不标）
- 求证(2)「AM∥CN」→ AM、CN 线段已画；**∥ 关系不画**（平行是证明结果，不标平行标记）

**⚠ 判别不确定时的兜底（必读）**：**一旦分不清对象属于题设还是结论，立即查阅 `type-notes.md` 的「题设-结论区分」完整示范**（查阅保持正确率）；type-notes 未覆盖时，**保守按"题设才画"处理**——宁可少画疑似结论对象，不泄露答案。

## 阶段 2：确定构造顺序

这是最关键的一步。将点的构造顺序类比尺规作图来安排：

### 构造策略（按优先级）

**策略 A — 水平基准优先（按三级优先级选择锚边）**：
1. **优先级判断**：①坐标系存在 → x 轴即水平，无需选边；②主图形为正方形/矩形/平行四边形/梯形 → 选长底边；③其他 → 选最长线段
2. 这条水平线段作为整个图形的"锚"，后续所有点以此为基准构造
3. 以已有点为基准，用约束求解下一个点
4. 重复直到所有点就位
5. **圆相关图形**：水平基准 = **整个图形中最长的线段**，不预设直径优先——可能是直径、穿过圆的割线、或一端在圆上的线段；仅当圆相关线段确为最长时才用它

**策略 B — 从直角顶点开始**（直角三角形、矩形）：
1. 将直角顶点放在原点
2. 两条直角边沿坐标轴放置（斜边自然确定，且斜边将成为最长边，自动满足水平偏好）

**策略 C — 从对称轴开始**（等腰三角形、菱形）：
1. 将对称轴放在 y 轴或 x 轴上
2. 对称放置两侧点

**动点模式构造（阶段 0 触发动点模式时）**：
1. 静态锚定：先按策略 A/B/C 固定静态点（圆心、线段端点、基准点、坐标轴交点）
2. **逐个动点参数化**：每个一级动点一个参数——圆上动点 θ（默认取 θ=1.2 rad 附近非特殊位置）、线段上动点 t（默认 t=0.5）、直线上动点 t（默认非特殊值；坐标轴动点如"动点 E(m,0)"取 m=1 附近）
3. **识别关联点**：扫题面找位置不由自身参数决定、由一级动点/静态点派生的点（对称、中点、定比分点、平移、正方形顶点、圆/线段上的从属点等）→ 按题面关系推导，进 deps
4. 依赖链排序：关联点按依赖顺序列出（op 求值拓扑序，禁环）
5. 跳过旋转/翻转兜底：构造时直接让基准边水平、图形主体朝上（dynamics 模式不参与预处理旋转）

**动点层级梳理（动点模式，先理层级再算坐标）**：
- **第一级 = active**：独立自由动点，**可有多个**（每个一个参数：θ/t；t 无界时对应直线型动点），并行独立，互不派生
- **第二级 = deps 关联点**：直接引用一级动点的非独立点（按题面关系推导：对称→symmetry、中点→midpoint、平移→translate、正方形顶点→square_vertex 等）
- **第三级及以上**：`deps` 中引用其他关联点的点，沿依赖链逐级确定，禁环
- **确定方法**：关联点位置由「被引用点 + 题面关系」确定；**尺规语言**描述几何意义（如中心对称 = 连接动点与对称中心并延长取等距点），**op 直接计算**坐标，两者数学等价、互为校验；op 表没有的关系 → Python 直接推导坐标公式（阶段 3 算 LUT 或扩展 op），JS 端无感知
- 示例：一级动点乙在线段上（t 参数）→ 关联点甲 = 一级动点乙 + 平移向量（如"随动点右移 3"，坐标 = 一级动点乙坐标 + (3,0)）

### 构造步骤的表述格式

对每个待求点，用以下格式描述：
```
点C：以 A 为圆心 r=AC、B 为圆心 r=BC 的两圆交点（SSS 构造）
点D：AB 中点（定比分点 λ=0.5）
点E：过 C 作 AB 的垂线的垂足
```

### 3.2 坐标求解执行规范

1. **第一步**：确定比例尺。找到题目中所有已知长度的边，选最长的作为"基准边"，设其长度为实际值（如 AB=5 则直接用 5）。如果题目没有给任何具体长度，取第一个出现的边长为 1。
2. **识别自由度**：区分硬约束（等式/比例关系，必须精确满足）和自由参数（硬约束未锁定的角度或长度，可自主选择）。选择自由参数时遵循"中庸原则"（角度 30°~60°，长度与已有边同量级）。**选定后在输出中告知用户你取了什么值**（如"取 ∠C=50°"），用户可随时要求调整。
3. **放置前两个点**：将基准边的一个端点放在原点 `(0, 0)`，另一个放在 `(len, 0)`。
4. **逐步添加点**：按阶段 2 的构造顺序，每求出一个点就 `print(f"点X = {coord}")` 验证。
5. **验证约束**：所有点就位后，打印关键边长和角度，与题目约束对比。如果不符，修正。**注意 `angle_at(p, a, b)` 顶点是第一个参数 p**（∠APB），返回有向角可能为负**：平分/倍角/相等关系看角度差值（两两相减≈0）而非绝对值；验证直角（90°）建议用点积 ≈ 0 或 `angle_between_deg`，勿因符号误判失败。**numpy 2.x 兼容**：2D 叉积一律用标量 `v1[0]*v2[1] - v1[1]*v2[0]`（算法库 `angle_at`/`eval_op` 已实现），**禁止对 2D 向量调用 `np.cross`**（numpy 2.x 要求 3D 向量，抛 ValueError）。
6. **跨度大方向水平 + 最长边水平 + 方向归一化**：① **跨度大方向水平（2026-08 自动执行）**——若图形 y 跨度显著 > x 跨度（高瘦），预处理区自动旋转 90° 使跨度大方向变水平（配合画布高宽比约束 [1,1.5]，避免高瘦图形在宽画布中只占中间竖条）；**坐标系跳过**（x 轴水平规则优先，见 4.2）；② 找出最长的绘制线段，旋转使其水平（跨度方向已水平后通常跳过）。**长底边保护（2026-08 收紧，硬规则 #5）**：仅当主图形长底边已水平——存在**水平且长度 ≈ 最长线段（≥0.8× 最长）**的线段——才跳过旋转，保护正方形/矩形/平行四边形朝向；**任意短水平线段（拆线/辅助线/恰好水平的边）不构成跳过理由**，否则斜主图形的旋转兜底被误跳过、最长边保持倾斜（如"最长边 AB 斜 + B'D 拆出的短水平段"场景）。**⚠ 拆线合并（2026-08，硬规则 #5"整图最长线段"）**：最长边检测**基于合并拆线后的完整边**（虚线拆线/落点拆线把完整边拆成多段，如 AB→(A,D)+(D,B)，直接在 segments 上检测会退化为"拆分段里最长"、水平基准漂移，如 AB 被拆后 AC 当选）——预处理区自动 `_restore_full_edges` 合并**共享端点且中间点在两端点之间**（|a-x|+|x-b|=|a-b|，拆线的精确特征，不误合并延长线交点）的连续段恢复完整边（仅用于检测，不改 segments）。然后检查所有点的平均 y 坐标，若 < 0（图形倒挂），整体垂直翻转。确保图形主体在水平线上方。
7. **近似角策略**：已知某角三角函数值（cos/sin/tan 任意）时，画图可用近似整数角（视觉无差、省资源）。但**验证与画图解耦**：
   - 验证用对应反函数对原值独立反代：`acos(值)` / `asin(值)` / `atan(值)`，勿复用画图近似角
   - **象限校正**：sin/tan 反函数默认返回锐角，若角实为钝角需 `180° - asin(值)` / `180° + atan(值)` 校正
   - 禁止凑特殊角后拿它做验证（如取 cos 48° 却用 2/3 对比）
8. **🛑 防呆检查点（阶段3出口）**：确认以下每一项再进入阶段4——
   - 打印了每条约束的"实际值 vs 期望值"对比
   - 所有偏差 < 1%
   - 若题目没给数字，已打印自己设的默认比例（如 r=5 或 基准边长=6）
   - print 无 ✓/✗ 等特殊符号（用 [OK]/[FAIL] 替代；中文描述性 print 允许）
   - 孤点已检测：segments 中每个点出现 ≥ 2 次
   - **required_segments 完整性（2026-08）**：数据区 `required_segments` 列出题面所有要求出现的线段（图形边/连接线/目标线段/距离约束线段；**与 segments 同粒度——拆线场景写拆分段**，见 4.2），保存前自查对照 segments（忽略顺序）——缺失已自动补入并打印 [FAIL] 提示自查；全部在则 [OK]
   - 动点模式（dynamics 非空）：已生成 luts 预计算表并验证——表内无 NaN、长度符合采样约定（圆 720 / 线段 101 / 曲线 200）、抽样点与 op 求值/解析解一致（偏差 < 1%）；⚠ 有 curve 类型动点时必须生成其 LUT（强制），已打印 [OK]
   - **动点边界**：一级动点 t/θ/x 范围与题面一致（能算必算，默认仅限完全未限定）；二级动点可达域由一级范围映射（抽样验证一级两端 → 二级两端在画布内），已打印 [OK]

### 3.3 常见构造模式速查

| 题目条件 | 构造方法 |
|----------|----------|
| 已知三边长 (SSS) | `circle_circle_intersection` |
| 已知两边及夹角 (SAS) | 放两边 → `rotate_point` 或 `rotate_vec` |
| 已知两角及夹边 (ASA) | 放底边 → 从两端点画射线 → `line_intersection` |
| D 在 AB 上，AD = x | `a + normalize(vec(a,b)) * x` |
| D 是 BC 中点 | `midpoint(b, c)` |
| AD 是角平分线 | 角平分线定理：`division_point(b, c, AB/AC)`。**方向判定**：角平分线在角内部、向图形内侧延伸——先确定角的两边方向（如 ∠OAB 是 AO 与 AB，勿误取 x 轴正方向），再取内角平分，画到三角形/角内部，勿画到外部 |
| AD ⊥ BC（高线） | `foot_of_perpendicular(a, b, c)` |
| 平行四边形 ABCD | D = A + vec(B,C) 或 C = B + vec(A,D) |
| 等腰三角形 AB=AC | A 在 BC 的垂直平分线上 → `midpoint` + 垂直方向偏移 |
| 点关于线段翻折 | 垂足法：`H = foot_of_perpendicular(P, A, B)` → `P' = 2*H - P`。翻折命名按位置对应（如 ABCM→EFCM 即 A→E, B→F, C→C, M→M），验证失败时优先检查对应关系，勿怀疑顶点顺序。**⚠ 验证判据（3 条，2026-08）**：翻折是沿对称轴**直线**对称（折痕 AB 决定整条直线），验证用 ① `dist(对称中心点, P) = dist(对称中心点, P')`（如 DB=DB'）；② `P P' ⊥ 对称轴`（点积 ≈ 0）；③ **P P' 中点 H 在对称轴直线上**（叉积共线 `(H−a)×(b−a) ≈ 0`，**含延长线**——H 可落在折痕线段之外，勿用"H 在线段 AB 上"的线段内判断，否则翻折点远离折痕端点时误报 [FAIL]）。 |
| 已知角三角函数值（cos/sin/tan） | 优先余弦定理/点积直接用值；必须画角时用近似整数角，验证用对应反函数精确反代（注意 sin/tan 钝角校正，见 3.2 近似角策略） |
| 函数曲线（反比例/指数/幂/三角等） | 模型采样成点集放 `curves`：x 范围=目标显示范围、间距 ≤ 2% 跨度且 ≥ 100 点、**x 单调递增**（curve_at 插值依赖，多值曲线拆分多段）、渐近线爆炸点跳过；不无限延伸避免挤小其他内容 |

### 3.4 动点模式：dynamics op 规范

动点模式下，`dynamics["deps"]` 中的每个导出点是一个 op 表达式。**Python 生成器（阶段 3）与 HTML JS 求值器（阶段 4）必须实现同一套 op、同一语义**，支持以下 op（新增 op 需按「双端同步」流程：Python eval_op + JS OP + 本表同时更新）：

| op | 参数（args） | 数学含义 | 尺规构造描述 | 示例 |
|----|--------------|----------|--------------|------|
| `symmetry` | `[center, point]` | point 关于 center 的中心对称：`P = 2*center − point` | 连接 point 与 center 并延长到 P，使 centerP = center·point | `{"op":"symmetry","args":["一级动点","静态点"]}` → 二级动点 = 2×一级动点 − 静态点 |
| `reflect` | `[point, a, b]` | point 关于直线 ab 的轴对称（垂足法：H 为垂足，P'=2H−P） | 过 point 作 ab 的垂线，垂足 H，延长到 P' 使 HP'=HP | `{"op":"reflect","args":["导出动点","静态点甲","静态点乙"]}` |
| `midpoint` | `[a, b]` | 中点 `(a+b)/2` | 连接 a、b，取线段中点 | `{"op":"midpoint","args":["静态点甲","静态点乙"]}` |
| `ratio_point` | `[a, b, ratio]` | 定比分点 `(a + ratio·b)/(1+ratio)`，ratio=AP/PB（=1 即中点） | 连接 a、b，按 AP:PB=ratio 取点 | `{"op":"ratio_point","args":["静态点甲","静态点乙",2]}` |
| `point_on_circle` | `[center, radius, theta]` | 圆上点 `center + r·(cosθ, sinθ)`，theta 弧度 | 以 center 为圆心、radius 为半径作圆，沿 θ 方向取点 | `{"op":"point_on_circle","args":["圆心",1.0,0.5]}` |
| `point_on_segment` | `[a, b, t]` | 线段上点 `a + t·(b−a)`，t∈[0,1] | 在线段 ab 上从 a 向 b 取 t 比例的点 | `{"op":"point_on_segment","args":["线段端点甲","线段端点乙",0.5]}` |
| `square_vertex` | `[a, b, dir]` | 以 a→b 为边向 dir 侧作正方形，下一顶点 = `b + R90(dir·(b−a))`（dir=+1 逆时针 / −1 顺时针） | 以 ab 为边向 dir 侧作正方形，取下一顶点（再调用一次可得另一相邻顶点） | `{"op":"square_vertex","args":["边起点","边终点",1]}` |
| `translate` | `[point, 向量]` | 平移：`point + 向量`（关联点常见关系，如"随动点右移 3"） | 沿向量方向平移 point | `{"op":"translate","args":["一级动点甲",[3.0,0.0]]}` → 关联点 = 一级动点甲 + (3,0) |
| `line_through_intersect` | `[p, dir, a, b]` | 过 p 沿方向 dir 作直线与直线 ab 的交点：`denom = cross(dir, b−a)`，`abs(denom)<1e-9 → [NaN,NaN]`（平行无交点）；`s = cross(a−p, b−a)/denom`，`Q = p + s·dir` | 过点作平行线交直线（PQ∥x 轴 → dir=[1,0] 水平；∥y 轴 → [0,1]；∥斜线 → 方向向量） | `{"op":"line_through_intersect","args":["一级动点甲",[1,0],"直线端点乙","直线端点丙"]}` → 关联点 = 过一级动点甲的水平线与直线 端点乙-端点丙 的交点 |
| `seg_intersect` | `[a, b, c, d]` | 直线 ab 与直线 cd 的交点：`denom = cross(b−a, d−c)`，`abs(denom)<1e-9 → [NaN,NaN]`（平行无交点）；`t = cross(c−a, d−c)/denom`，`P = a + t·(b−a)` | 两条线段（视为直线）相交，交点即 P（如"连接 DE、CF 交于点 P"） | `{"op":"seg_intersect","args":["静态点D","一级动点E","静态点C","一级动点F"]}` → 关联点 = DE 与 CF 的交点 |
| `circle_line_x` | `[center, other, y, sd]` | 圆 (center, r=dist(center,other)) 与水平线 y 的交点：`dy=y−center.y`，`abs(dy)>r → [NaN,NaN]`（水平线在圆外）；`dx=sqrt(r²−dy²)`，`x=center.x+sd·dx`（sd=+1 右 / −1 左） | 以 center 为圆心、过 other 的圆与水平线 y 的交点（翻折后落点、圆弧与水平线相交等，2026-08） | `{"op":"circle_line_x","args":["一级动点F","静态点A",3.0,1]}` → E = 圆(F,FA) 与 y=3 的右侧交点 |
| `curve_at` | `[curve_index, x源]` | 曲线采样上 x 处点：`x源` 为数值直用 / **点名取其 x 分量**（eval 后坐标取 `[0]`）；在 curves[curve_index] 采样上**线性插值**（`y = y₀ + t·(y₁−y₀)`，越界取端点；curves 缺失/越界 → `[NaN,NaN]`） | 把 x 代入函数曲线求 y（如"过 E 作 y 轴平行线交抛物线于 G"→ G = 抛物线在 E.x 处点，2026-08，轴上动点→曲线上关联点派生） | `{"op":"curve_at","args":[0,"一级动点E"]}` → G = curves[0] 上 x=E.x 处点（线性插值） |
| `rotate` | `[p, c, deg]` | 点 p 绕中心 c **逆时针**转 deg 度（顺时针用负值，如"绕某点顺时针旋转 90°" → deg=-90） | 以 c 为圆心、把 p 绕 c 旋转 deg 度 | `{"op":"rotate","args":["一级动点甲","定点乙",-90]}` → 关联点 = 一级动点甲绕定点乙顺时针 90° |
| `rotate_cw90` / `rotate_ccw90` | `[p, c]` | 90° 快捷（顺时针/逆时针），与 rotate(p,c,±90) 同数学、防符号偏差 | 绕 c 旋转 90° | `{"op":"rotate_cw90","args":["一级动点甲","定点乙"]}` |

规则：
- **args 中的元素**可以是：动点（`active`）、其他导出点（允许多级依赖链，JS 按拓扑序求值，禁止成环）、points 中的静态点、数值/坐标数组字面量，**或嵌套 op 表达式**（2026-08 JS 端已对齐 Python：Python 用 tuple/list `('op',[args])`（eval_arg 对两者一视同仁）、JS 用数组 `["op",[args]]`，两端同语义递归求值——如 `F = translate(["rotate_cw90",["E","A"]],[0,4])` 直接表达"绕 A 顺时针 90° 再平移"）。复杂关系**嵌套表达式与中间构造点拆链两种写法等价并存**，模型任选
- **数值参数**（radius / theta / ratio / t）直接写数值字面量
- **Python eval_op 已提供**：3.1 算法库的 `eval_op(op, args, pts)` 即 Python 端求值器（与 4.1b JS OP 同语义：rotate 逆时针为正、度；point_on_circle theta 弧度；cw90/ccw90 复用同一数学；square_vertex dir=+1 逆时针/−1 顺时针），复制即用，**禁止另写符号约定不同的实现**（历史教训：rotate 符号偏差根源于双端各写各的）
- **两侧一致性**：阶段 3 用 Python 等价求值器（= eval_op）按默认参数算默认位置，与 points 对比**相对偏差 < 1%**（公式 `dist(计算, 期望) / 坐标量级 < 0.01`，坐标量级取 |x|、|y| 的最大值；勿用绝对偏差，坐标量级 ~8 时绝对 0.01 可能误判）；JS 侧浏览器实时重算，结果必须与 Python 相同（含符号约定：角度统一弧度、逆时针为正）
- **生成流程**：阶段 3 末尾打印 Python 等价求值器的默认位置对比（纯 ASCII [OK]/[FAIL]）；PNG 输出默认位置静态图；HTML 的 `DYNAMICS` JSON 由 generate_html 按 `dynamics` 变量自动嵌入，无需手写
- **readouts 表达式规范**：`expr` 必须为带乘号的线性形式 `a*p[0]+b*p[1]+c`（如 `"3*p[0]+4*p[1]"`），或 `"p"`（输出第一个导出点坐标对）；`fmt` 用 `%.2f` 或 `(%.2f, %.2f)` 形式。**⚠ 只对第一个关联点求值（2026-08 说明）**：readouts 的 `p`/表达式均针对 `deps` 字典**第一个**关联点——多关联点想读数时按需调整 deps 顺序（把目标点放首位），或扩展机制（当前不改）
- **LUT 预计算表（luts）**：阶段 3 用 Python 等价求值器按采样生成每张位置表并写入 dynamics：圆上动点 θ 按 0.5° 步长采样 720 点（JS 下标 `i = round(θ·360/π) mod 720`，θ 为弧度）；线段动点 t 按 0.01 步长采样 101 点（JS 下标 `i = round(t·100)`）；曲线动点 x 在 `[x_min,x_max]` 均匀采样 **200 点**（JS 下标 `i = round((x−x_min)/(x_max−x_min)·199)`，**⚠ 曲线动点强制 LUT**——JS 无法解析任意函数，必须查表）。**实际使用（2026-08 对齐实现）**：一级 **curve** 动点的位置与拖拽吸附查 LUT（paramPoint/dragMove 最近邻）；**轨迹显示**由 buildTrajectory 直接取表（deps 点无表时走参数采样分支兜底）；**deps 关联点位置由 `evalPoint` 实时 op 求值（对 deps 永远重算、不查表**——lookupOrEval 的查表分支对 deps 点无 params 恒不命中）。**⚠ luts 可空**：关联点直接引用一级动点（无二级链）时留空 `{}`，走 op 公式实时求值
- **二级及以上动点求法（引导）**：先识别几何变换（中心对称/轴对称/中点/定比分点/正方形顶点/平移/位似/任意角旋转等）→ op 表有的直接套用，**op 表没有的用向量/坐标/尺规直接推导公式** → 用推导结果生成 LUT（有二级链）或直接走 op 公式（关联点无二级链）→ JS 只查表/求值（对具体求法无感知）。**⚠ 边无方向**："以 XY 为边作正方形/等边"中边 XY **无方向**（X↔Y 对称）；构造方向由「题面方位词 + 字母顺序 + 题图/用户确认」共同决定，不可默认 X→Y 为有向边。**方位词 → dir**（沿 a→b 方向看）："右侧" = 顺时针 = **dir=−1**；"左侧" = 逆时针 = **dir=+1**。题面只用方位词无图、或仅说"作正方形 ABCD" → 按惯例默认（四边形字母逆时针；"右侧作"=顺时针 dir=−1、"左侧作"=逆时针 dir=+1），**不询问用户**——用户可用 HTML 镜像/旋转自行纠错（见自查清单方向条目）。**rotate/rotate_cw90/rotate_ccw90 已预置**（4.1b JS OP + Python eval_op 两侧同语义：角度统一"逆时针为正、度"）；仅更冷门的变换（位似/投影/任意缩放等）才需按「双端同步」流程扩展（Python eval_op + JS OP 同时加）

### 4.2 绘图规范

**样式规则**：
- 所有线条统一黑色（`#000000`）、等宽（1.5pt）
- 主干线段：实线；辅助线（延长线、构造线）：实线
- 点：黑色实心小圆，大小与线宽一致
- 默认不画装饰性标注（等长标记、角度弧线一律不画）；**直角标记为可选项**——仅用户明确要求"标直角/标垂直"时画（见硬规则 3）。**静态模板（4.1）**：数据区 `right_angle_marks = [["顶点","边上点甲","边上点乙"], ...]`，PNG 与 HTML **双端口径一致**（绘图执行区 + generate_html 共用数据源；尺寸 = 0.1×min 短边，clamp 到 0.8%~1.7% 图形跨度，与动点模板同公式，2026-08）。**动点模板（4.1b）**：`dynamics.right_angle_marks`（JS 实时跟随动点）
- **题面条目线段完整性（必画，2026-08）**：题目中出现的**所有线条都必须连接**，**一条不漏**：① 图形边（正方形/矩形/平行四边形等封闭图形的全部边）；② 连接线（"连接 AD"）；③ 目标线段（所求值两点距离）；④ 距离约束线段（AB=5）；⑤ **角的两边**（∠ABC → 边 BA、BC 必画，角度弧线仍不画）；⑥ **几何要素线段**（题目明确提到的高线/中线/角平分线/垂直平分线/对称轴/翻折折痕/中位线/直径/半径/弦/切线等）；⑦ **关系载体线段**（∥/⊥/共线/相等关系中的线段，如 AB∥CD 的 AB、CD）。实现：数据区 `required_segments` 列出题面所有要求出现的线段（**与 segments 同粒度——落点拆线场景写拆分段**，如 DC 拆成 (D,E),(E,C) 则 required 写 (D,E),(E,C) 不写 (D,C)，见落点拆线条款），保存前自查（预处理区，**先于孤点补连**）对照 `segments`（忽略顺序），缺失**自动补入并报 [FAIL]**（提示模型自查漏画）。**执行顺序：完整性检测 → 孤点补连**——先抓"正方形只画 3 边"这类图形边不完整，避免缺边走到孤点补连（最近点可能连错）
- **孤点连接**：每个点应至少与 2 条线段相连。若某点只连了 1 条线段（悬空端点），优先根据几何经验补一条最自然的连接（如封闭三角形、连到最近已有点）；若无法判断，询问用户"X 点还需要连到哪个点？"。**辅助交点例外**：仅作为辅助线交点（如 BE 与 AC 的交点 E）不独立成点——要么不标字母（交点自然呈现），要么加入 `isolated_exempt`（**防孤点检测补连**，标签保留）与 `label_exempt`（**不标标签**）——防补连由 isolated_exempt 承担、不标字母由 label_exempt 承担。**曲线/直线交点豁免**：与曲线（抛物线/函数图像）或直线相交产生的交点——不是任何线段的端点、但本质是两种线相交（如抛物线与 x 轴交点、水平线与直线 BC 的交点 Q）——**不视为孤点**，默认加入 `isolated_exempt` + `label_exempt`（不补连且不标标签），禁止孤点检测自动补连多余线段（如补连 A-C）。
- **⚠ 落在线段上的点（中点/垂足/圆心/分点）**：如"E 为 BC 中点"，E 在线段 BC 上但不是端点，线段扫描 deg=0 会被孤点检测误判并自动补连多余线段——处理：把所在线段拆成两段（`('B','C')` → `('B','E'),('E','C')`），或加入 `isolated_exempt`；优先拆线（保留该点在线段上的位置关系）。**⚠ 拆段顺序必须与落点沿线实际顺序一致（2026-08）**：多个落点在同一线段上时（如 BD 上依次 B、M、N、D），拆段必须按沿线顺序写 `('B','M'),('M','N'),('N','D')`——**不可**写成 `('B','N'),('N','M'),('M','D')`（B-N 会跨过 M 点、N-M 与 BN 重叠，PNG/HTML 双端视觉错乱）。**⚠ 检测盲区（必读）**：完整性检测只查线段存在性（`(a,b) in segments`）、孤点检测只查点数（deg≥2）——**两者都不查拆段顺序**（2026-08 起模板预处理区已加 3c/3d 自动顺序检查 `[WARN]`，见自查清单，模型自查仍需了解判据）。顺序写错的后果分两种情况：① **required 与 segments 同步错序**（required 和 segments 都写错序，如 `('B','N'),('N','M'),('M','D')`）→ **静默错误**（脚本不报错、PNG/HTML 都错乱，B-N 跨过 M 点、N-M 重叠）；② **required 对、segments 错序** → 完整性检测会 [FAIL] 并自动补入正确段，以 [FAIL] 提示自查。**模型自查（机械检查式）**：每个拆分段必须首尾相接、且中间点严格位于其两端之间——三点 P1/P2/P3（P2 在中间）判据：**共线**用叉积 `cross(P2−P1, P3−P1)`，`|叉积| < 1% × |P1P3|²` 视为共线（与阶段 3 容差惯例一致）；**顺序**用内积判 `dot(P2−P1, P3−P2) > 0`（P2 在 P1、P3 之间）。**⚠ 两套容差（2026-08）**：模板自动检查（3c/3d）用**严格**共线判据 `|叉积| < 1e-9 × max(1, |va||vb|)` 与严格段内判据 `|d1+d2−d| < 1e-6 × max(1, d)`（精确坐标假设）——模型自查用宽松的 1% 判据（便于手算时含入误差）；两者目的不同：模型自查防大错、自动检查抓精确漏网，**近似共线（残差在 1% 与 1e-9 之间）会过自动检查**（按精确坐标约定，勿依赖近似小数）。**⚠ required_segments 同步写拆分段（2026-08）**：拆线后 `required_segments` **必须同步写拆分后的段**（`('D','E'),('E','C')`，不写 `('D','C')`）——否则完整性检测会把题面原线段（如 (D,C)）误判为缺失自动补入，与拆线段重叠并报 [FAIL] 误导模型自查（见 4.2 完整性条款）。**⚠ 拆线不影响水平基准（2026-08）**：拆线后最长边水平检测（3.2 第 6 条）由预处理区 `_restore_full_edges` 自动合并拆分段恢复完整边，水平基准仍为整图最长线段（与虚线拆线同，见虚线拆线第 7 条）
- **目标线段（必画）**：题目所求值表达式中的"两点距离"对应连线（如"求某点甲到某点乙距离的最小值"→ 连接 点甲-点乙）即使题干没说"连接"也要画进 segments——**不受"已连 2 条线段"限制**（两端点即使 deg≥2 也补上目标线段）；它给出所求值的几何对象。从所求值表达式解析两点距离：如 "EH 的最小值" 中的 EH、"3BH+5DH" 中的 BH 与 DH
- **圆弧/扇形**：题目含"画弧/弧 AB/扇形"（如尺规"以 A 为圆心、r 为半径画弧"，或"扇形 OAB"）→ 用 3.1 的 `arc_points(圆心, 半径, θ0, θ1)` 采样弧上点（θ 弧度、逆时针），以曲线方式渲染（实线/虚线按需）；**扇形** = 弧 + 两条半径线段（加入 segments：`(圆心, 弧端点甲)`、`(圆心, 弧端点乙)`）；θ 范围来自题面（"弧 BC" → 由 ∠BOC 或圆心角定）；不涉及圆弧/扇形时不要用（普通整圆仍走 circles）
- **开放图形覆盖动点范围（硬约束）**：直线/射线/函数曲线（开放图形）上可能有**任意层级**的动点（一级 / 二级 / 三级及以上，如关联点链 C→D→E 中 E 落在曲线上），图形绘制长度必须**两端超过该动点可达范围**——① 可达范围算法：一级动点按自身 t/x/θ 范围算；二级及以上按**沿 deps 依赖链从其一级动点范围逐级映射**得到（如 P 在 "1≤x≤3"、Q 是 P 的对称点 → Q 可达域 = P 范围经对称映射）；② 直线/曲线采样 x 范围 ⊇ 该可达 x 区间；③ 射线/线段同理延伸至覆盖；④ 动点所在图形画成有限线段（segments）时，线段两端不得截断动点可达位置（必要时延伸或改直线采样）。**否则任一层级动点拖到图形外，输出不稳定**
- **动点可达范围纳入画布（硬约束，2026-08）**：动点模式（dynamics 非空）下，**动点可达范围必须纳入画布计算**——PNG 与 HTML 共用 x_min/x_max/y_min/y_max，否则拖动动点到极端位置时图形/标注移出画布与 SVG viewBox。由执行区自动调用 `compute_dynamic_extent`（template_motion.py）实现，**模型无需手工算画布范围**（早期手工 max(y_max, 6.0) 硬编码已废弃）：① 一级动点按类型取可达边界（segment 端点已在 points 跳过 / circle 圆心±半径 / line 基准点±dir·t 两端 / curve 曲线采样 x∈[x_min,x_max] 段极值）；② 二级及以上动点**仅对 points 中的可见关联点**沿 deps 链找被引用一级动点、参数网格组合采样 + eval_op 映射取极值——**中间构造点（不在 points、不显示）豁免画布采样**，否则会凭空拉大画布（如 G=rotate_cw90(E,A) 可达 y∈[-4,0] 会把下界拉到 -4，正方形下方多出空白）；③ params 的 center/point/a/b 应为 points 内静态点名（动态圆心属边缘场景；代码已加 KeyError 防护——误引用 deps 点时跳过该动点的画布扩展/覆盖采样，不崩溃，2026-08）；④ B2（check_open_coverage）同样只校验 points 中可见 deps 点，中间构造点不参与覆盖校验（防 line/curve 一级动点时误报 FAIL）
- **双渲染路径一致性（硬约束）**：skill 有两条渲染路径——PNG（matplotlib，数据区 + 绘图执行区）与 HTML（generate_html，只读 `segments`/`circles`/`curves`/`points`/`dynamics` 数据源）。**几何线条（含开放图形覆盖动点范围）必须通过数据区表达**，让 PNG 与 HTML 共用同一数据源：① 直线（如"直线 BC"）→ 加入 `curves` 采样（x 范围覆盖动点可达域，直线型检测已支持）；② 射线/延长线段 → 延长端点算进 `segments`（延长点作为辅助点：加入 `isolated_exempt`（不补连）+ `label_exempt`（不标标签））。**禁止用绘图执行区扩展区手绘（`draw_ray`/`draw_segment` 直绘）承担几何表达**——扩展区是 PNG 独有（ax.plot），HTML 的 generate_html 不感知，会导致双端口径不一致（实测：延长线画在扩展区，PNG 覆盖了 Q 可达域、HTML 里 Q 拖出 BC 线段外）。扩展区仅供装饰性绘制（直角标记等）
- **内切圆**：题目含"内切圆/内接"（圆与三角形各边相切）→ 圆心 = 三角形**两条角平分线的交点**（内心），半径 = 圆心到任一边的垂直距离（`foot_of_perpendicular` 求垂足后取 dist）；画圆走 circles；外接圆仍按三点共圆（中垂线交点）
- **虚线拆线**：**在旋转和翻转之后执行**。当某线段需改为虚线且处于一条更长的实线上时：
  1. 找出包含该虚线段的整条实线（如 BD 虚线在 AC 实线上）
  2. 以虚线两端点为分界，将整条实线拆成若干段
  3. 非虚线部分保留实线（如 AD、DC），虚线目标段改为虚线（如 BD）
  4. 从 segments 列表中移除原实线，加入拆分后的各段
  5. **修改路径**：拆线后，虚线段放入 `dashed_segments`，其余实线段留在 `segments`（绘图执行区第 0 步会自动去重）。**⚠ 虚线段必须同时进 segments（2026-08）**：虚线段**同时放入 `segments` 和 `dashed_segments`**——进 `segments` 供**孤点检测计数**（deg≥2，否则只连虚线的端点被判孤点、自动补连多余实线，图形错乱），进 `dashed_segments` 供虚线渲染；绘图执行区 0b 互斥步骤自动把 `segments` 中的虚线段移除（防叠画），两处同放安全。**仅拆分段场景**（虚线是拆线的一部分）不受影响：拆线后拆分段本就在 segments（实线段），虚线目标段再进 dashed_segments 即天然满足
  6. **⚠ required_segments 同步写拆分段（2026-08）**：拆线后 `required_segments` **同步写拆分后的段**（AC 拆成 (A,D),(D,C) 则 required 写 (A,D),(D,C)，不写 (A,C)）——否则完整性检测把原实线 (A,C) 判缺失补入实线，与拆分段重叠且实线压虚线（与落点拆线同型，见落点拆线条款）
  7. **⚠ 拆线不影响水平基准（2026-08）**：拆线后最长边水平检测（3.2 第 6 条）由预处理区 `_restore_full_edges` **自动合并拆分段恢复完整边**（共享端点且中间点在两端点之间），水平基准仍为整图最长线段——拆线不会使最长边"消失"、不会漂移到拆分段里最长（如 AB 拆成 (A,D),(D,B) 后仍以 AB 为基准，而非 AC）
- **坐标系规则**：涉及函数图像、坐标轴的题目（含"一次函数""反比例函数""抛物线""坐标系""x轴""y轴""象限"等），默认**不标任何数字**。轴只画两条带箭头的垂直线，交点标 `O`；点只标字母不标坐标值。用户反馈明确要求时才补数字。输出时简短告知"坐标轴为示意，未标注数值"。**水平规则 = x 轴水平（最高优先级）**：坐标系题**不做跨度方向旋转/最长边旋转/垂直翻转**（轴固定）；画布高宽比约束 [1,1.5] 坐标系也应用（画布宽≥高适配宽屏，数据不变形）。

**标注规则**：
- 仅标注点的字母
- **坐标系题**：O 是轴原点，由轴代码标注；`points` 不含 O（或 `auto_label` 跳过 O），避免重复标注。**⚠ O 进 points 画线段（2026-08）**：若需画以 O 为端点的线段（如 OD），O 进 `points` 后**必须加入 `isolated_exempt`**——否则孤点检测把 O（只连 1 条线）补连到最近点、图形错乱（标签不重复：auto_label/label 生成已跳过恰在原点的 O）
- 字母放在点外侧，避免与线条重叠

**比例规则**：
- 始终保持等比例（`ax.set_aspect('equal')`）
- 图形居中，四周留白 25%
- 如果图形过扁或过长，画布自适应调整

**输出格式规则**：
- 输出 PNG（300dpi，直接插入 Word/PPT）+ HTML（可旋转/镜像交互预览）
- 如需修改图形，通过对话反馈迭代（阶段 5），不靠手动编辑源文件
